# Saved authoring projects

In the shared Rust engine we save authoring work as a versioned ZIP archive (`.rominabox`, format version 3). It contains `manifest.json` and the files listed in the manifest: the game's files under `content/`, its patches, any firmware under `firmware/`, custom shader files, and the icon and background under `assets/`. The manifest contains the portable authoring choices. It leaves out the output folder, the runtime kit, the core path, caches, saves, credentials and anything else that belongs to one computer.

`project-save` and `project-open` are commands of `rominabox-cli`, with JSON requests and JSON Lines results. We refuse to save over an existing archive. To open a project, you give a new extraction folder, whose parent must exist, and the settings in the result have paths into that extracted copy. When loading, we refuse path traversal, symbolic links, files not listed in the manifest, unsupported format versions, more than 1,024 entries, a manifest over 1 MiB, a game file over 8 GiB, a picture over 32 MiB and more than about 10 GiB of content in all. We limit what we actually read and check the extracted sizes instead of the sizes in the ZIP headers.

We copy files as streams and store them without ZIP compression, so large disc images stay within bounds and the size of the archive is predictable. We write a save beside its destination and then publish it with a hard link, which never replaces an existing archive. Saving therefore needs a file system with hard links. We remove the staged copy once the archive is published.
